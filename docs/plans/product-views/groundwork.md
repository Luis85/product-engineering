# Groundwork intake for the Sol 6.2 orchestrator

Run this intake in the checkout that contains the groundwork delivered by the other session. Its purpose is to give the first view agent an exact target commit, working native entry point, persistence API and verification command. The repository builds the [shell blueprint](../obsidian-plugin-shell-blueprint/README.md) in task order. The product packets start after that handover.

## Record the baseline before dispatch

1. Record the checkout, branch, `git rev-parse HEAD` and `git status --short`. Read the applicable `AGENTS.md`, [glossary](../../../GLOSSARY.md), root README, blueprint acceptance report and architectural decisions present on that revision. Preserve concurrent work. A sequence of plan files documents intent and needs confirmation in source and tests.
2. Match the implementation to the table below. Record the **actual paths, public symbols, coverage and limitations** in the implementation run's log. Read the manifests to find renamed modules. Check whether Git, link resolution, note indexing, local providers and the item tracer already have usable adapters. Share this inventory with each assigned agent.
3. Use the checkout's pinned Node/npm and lockfile. Run `npm run verify` and record its exit code. Inspect `scripts/verify.mjs` for its actual coverage. Exercise the harness with `npm run dev:ui`; use the completed blueprint's native end-to-end command on a supported host with a disposable test vault. The browser harness alone cannot establish that edits work inside Obsidian. Record any unavailable environment and its effect on acceptance.
4. Compare outstanding groundwork with the other session's delivery. If a required planned note service has not landed, identify the exact missing task and dependency before scheduling the affected writer. Do not create a second note store, UI framework or runtime to get a screen working. Product-specific gaps such as a Git adapter belong to their owning packet. Publish the available seams and the agreed [cross-view contracts](contracts.md) before dispatching V01.
