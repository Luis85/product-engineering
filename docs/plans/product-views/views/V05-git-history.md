# V05 · Git history and committing one artifact

**Outcome.** A user can tell whether the note has unsaved text, saved changes or a clean committed version, inspect the actual differences, and commit the intended file. A release can identify the exact committed revision it used.

**Inputs.** Requires the project repository/branch settings from V02 and stable note identity, vault file resolution and save behavior from V03/V04. Reconcile [groundwork](../groundwork.md), [shell blueprint](../../obsidian-plugin-shell-blueprint/README.md) and [shared contracts](../contracts.md) with the delivered checkout. Use the [clickdummy](../../../concept/Product-Engineering-Clickdummy-Story-Maps.html) at `#/project/kundenportal/doc/PRD-03` → **Git History** and an item's **Git-Historie öffnen**. Inspect `gitItem`, `gitPanel`, `openGit`, `gitCommitForm`, `workingChanges`, `diffMarkdown` and `documentStateMeta`.

## Implement this slice

- Reuse any delivered Git service after testing it against a temporary repository. If absent, own the project-scoped application port and native desktop adapter for repository discovery, per-file status/history, blob comparison and explicit commit. Resolve the project note against the local worktree; the configured remote slug is only a repository identifier. Use actual full object IDs internally, native author/date and real file bytes. Handle spaces, renamed paths and an initial commit. A missing executable, unavailable identity, missing repository or conflicted worktree needs a recoverable status.
- Show **Arbeitsstand vergleichen** and an ordered commit list with message, author, time and abbreviated hash. Compare the saved working file to its committed base. For a selected revision compare that file with its parent (label which parent for a merge). A new file compares with an empty base. Indicate additions and removals in text as well as color, wrap long paths and present **Keine Unterschiede** for a clean comparison.
- Reuse the same timeline/diff inside the V04 tab and the dialog launched by backlog items. Let the version selector scroll independently where useful; stack list and diff in narrow leaves. The commit form labels its target, validates a non-blank message, retains it after errors and returns to the timeline with the new revision selected and announced.
- **Commit ausstehend** or **Erster Commit ausstehend** leads directly to comparison or commit from note content. **Speichern und committen** saves the editor first, then obtains a message. If the user cancels at this point, the saved note remains pending. Revalidate file content and HEAD against what was reviewed. Serialize competing writes for the same target, surface a conflict for unexpected changes and preserve unrelated staged/unstaged files. Keep publication, branch switching and pushing outside this interaction.

## Test first and finish

1. In a disposable native Git repo with a local fixture author, create an untracked note, commit it, change title and body, commit again and inspect history after reopening the plugin. Assert full object IDs resolve to the expected blobs and parents. Stage an unrelated file beforehand and verify its staged and working content survives. Exercise rename, conflict, missing repository, invalid message and a second edit between comparison and submission.
2. In the routed native UI, compare a clean working copy, the first commit and the second. Check selection/announcements, additions/removals and unchanged text. Simulate a failed compare/commit and verify retry preserves context. Use [Git history](../../../concept/tests/test_git_history.py) and [knowledge commit actions](../../../concept/tests/test_note_commit_actions.py) for the interaction assertions.
3. From a dirty buffer choose save-and-commit, cancel the prompt, reopen it and commit. Check zero commits after cancel and exactly one after confirm. Repeat in a narrow popout with keyboard dismissal/focus return. Wire and run the same dialog from backlog item types when available. Ensure a release's frozen source hash and contents remain stable across later commits, as characterized in [delivery review](../../../concept/tests/test_delivery_review.py).

Deliver the repository/record resolution, head/status, immutable revision and content APIs, plus one shared history/commit surface. Report the adapter selected, platform exercised, failing-to-passing native tests and `npm run verify` exit code. Later feature requests take their immutable source references through this service.
