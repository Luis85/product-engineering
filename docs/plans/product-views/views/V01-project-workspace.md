# V01 · Project workspace and navigation

**Outcome.** Open the plugin in an Obsidian leaf, create or choose a product project, find its records, and return to the previous reading position. This packet owns the workspace frame, project picker, search and first landing route. [V22](V22-project-overview.md) owns the overview dashboard, delivery counts and guided planning journey.

**Inputs.** Start from the accepted [groundwork](../groundwork.md), [shell blueprint](../../obsidian-plugin-shell-blueprint/README.md) and [shared contracts](../contracts.md). Inspect the [clickdummy](../../../concept/Product-Engineering-Clickdummy-Story-Maps.html) at `#/project/kundenportal/overview`. Follow `chrome`, `projectMenu`, `paletteItems`, `search`, `toggleNavigation`, `rememberWorkspaceOrigin` and the `new-project` submit handler. Read V22’s route contract before choosing the landing component.

## Implement this slice

- Register a project-scoped route and workspace through the delivered [module registry](../../../../src/application/modules.ts), [app surface](../../../../src/presentation/app-surface.ts) and [navigation service](../../../../src/presentation/shell/navigation.ts). Restore the project ID, record ID and supported origin on leaf reopen. A missing project opens a recoverable project chooser. Use the existing ribbon/command entry point.
- Offer **Projekt anlegen** from both the empty state and **Projekt wechseln oder anlegen**. Collect Produktname, Kurzbeschreibung and Git-Repository. Show the effective project folder, branch and Backlog-Base through project administration. Create one persistent project context with an immutable identity. Handle colliding names/paths without overwriting existing vault files. Repeated submission must resolve to one project. Start at the project overview with its title and a real path into Wissen when V03 lands.
- Use the prototype's group order. Keep **Domainmodel** below **Wissen**. Add real destinations as their packets land. The desktop rail collapses to named icons and the main workspace uses the released width. Give narrow leaves a labelled drawer with a reachable opener, focus restoration and dismiss behavior. The right panel is dedicated to enabled AI. Omit the demo-tour control, signed-in avatar and Projektkontext button/panel.
- Open project search from a labelled control and a registered host command. Respect the shell's hotkey rules and user bindings. Search visible section names and current-project records by ID or title as contributors arrive. Preserve query, filters, scroll and invoking control when returning. Cancel navigation, including project switching, cleanly while a note editor resolves unsaved changes.

## Test first and finish

The project registration ties an actual project note to its Vault folder and assigned `.base`. On a clean plugin restart or re-adoption, discover the original project, note and Base by their stable identity. Test discovery also when local plugin preferences are absent. At the shell boundary, check that an existing native chat command or saved route cannot invoke even a configured CLI without explicit global consent. If the groundwork lacks a send guard, test and establish that default-off guard here. V23 owns the settings UI and explicit enable/disable lifecycle.

1. Start from an empty vault. Create two projects, restart the plugin, switch between them, open a deep link in a second leaf, and verify project-specific results even when two records have the same display ID. Assert cancellation/validation writes nothing and an existing folder's contents survive a collision.
2. In a split or popout leaf, collapse the rail, check usable width and accessible icon names, reopen the picker, dismiss search with Escape and confirm focus returns. Change the active project while another leaf is open. Its record and navigation history remain attached to its own project. Port the [sidebar](../../../concept/tests/test_sidebar.py), [workspace navigation](../../../concept/tests/test_workspace_navigation.py) and [project chrome](../../../concept/tests/test_project_chrome_and_owners.py) cases to the native harness.
3. Confirm that a dirty editor can resume after Back, and that palette selection returns to its origin. Use [knowledge review](../../../concept/tests/test_knowledge_review.py) and the initial creation sequence in [product flow](../../../concept/tests/test_product_flow.py). Add the cross-view assertions when V03/V04 arrive. Extend the existing [Obsidian navigation test](../../../../tests/e2e/specs/navigation.e2e.ts).

Return the project identity/lookup API, route builder, search contribution points, unsaved-navigation hook and native verification result. Later agents attach their own screens to the same frame. V22 fills the original overview route without changing existing entry points.
