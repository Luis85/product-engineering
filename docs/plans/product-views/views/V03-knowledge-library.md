# V03 · Knowledge library and creation

**Outcome.** A project member finds knowledge by subject, identifies the right note from its excerpt, and starts an appropriate draft in a few actions. An actor is a project knowledge note with kind **Mensch** or **System**.

**Inputs.** Requires V01's project context, project member choices from V02, [record services](../groundwork.md) and [shared contracts](../contracts.md). Read the [shell blueprint](../../obsidian-plugin-shell-blueprint/README.md). In the [clickdummy](../../../concept/Product-Engineering-Clickdummy-Story-Maps.html), open `#/project/kundenportal/knowledge` and inspect `knowledgeShelves`, `knowledgeResults`, `knowledgeEntry`, `knowledgeExcerpt`, `actorTypeField`, `newDoc` and its submit handler.

## Implement this slice

- Read project-scoped indexed vault notes. Reproduce the browsable groups **Produktgrundlagen** (Research, JTBD, Vision, PRD), **Akteure**, **Domainmodel**, **Design und Architektur** (Design, Styleguide, Designsystem, ADR), and **Konzepte** (arc42, Testkonzept, Betriebskonzept, Rollen- und Rechtekonzept, Freies Konzept). Preserve readable existing records with an unknown kind under Weitere Notizen. A single note identity drives the library, search, vault picker and domain editor.
- Show title and a short readable excerpt first. Keep type, ID, approval and assignment secondary. Search current-project titles, IDs, requirement IDs, types and owners. Support kind filters, the concept subtype and the actor subtype. Announce the result count, distinguish no matching results from an empty project, and offer **Filter zurücksetzen**. Preserve the selected filters, position and invoking row on return.
- **Notiz anlegen** uses the current type filter. Offer the actual templates and sensible editable defaults. A new note starts as **Entwurf** with **Nicht zugewiesen** unless a member is explicitly selected. Require the actor subtype for an Akteur. Seed the kind's Markdown headings and project-unique ID. A PRD can select one vision and multiple JTBDs and receives a stable requirement reference. Switching kinds must discard hidden fields belonging to the previous kind.
- Expose a single project-aware creation command accepting a template and optional typed origin (job, vision, deliverable). Validate the origin on submit, allocate the ID once, preserve the user's fields on a filename collision and leave no draft on cancel. Use the delivered note codec/record kit and update the index through its expected event flow. V04 owns the editor and detail route. Until it lands, an accepted create action can open the resulting Markdown file through the existing Obsidian note opener.

## Test first and finish

1. Create one human and one system actor, filter to each, find them by name and ID, reload and select either from the vault picker. Assert the files decode as typed actors and the team list remains unchanged. Editing an actor later must retain its ID. Port [actor notes](../../../concept/tests/test_actor_notes.py) and [owner defaults](../../../concept/tests/test_project_chrome_and_owners.py).
2. Search two projects with colliding titles/IDs and verify isolation. Test a zero-result filter, reset, a wide title in a narrow leaf, keyboard selection, focus/scroll restoration and an externally renamed file. Use [workspace navigation](../../../concept/tests/test_workspace_navigation.py) and [knowledge review](../../../concept/tests/test_knowledge_review.py). Exercise a delayed or failing index and its retry state with the native harness.
3. Add a PRD from its template and verify its frontmatter, body and optional relationships after a real vault reload. Cancel a second attempt and verify nothing was created. On V04 integration confirm **Entwurf im Editor öffnen** opens the correct buffer. On domain-model integration use [domain notes](../../../concept/tests/test_domain_notes.py) to prove both views resolve the same entity file.

Deliver the library/search projection, templates, validated create command, typed origin handling and detail-route destination to V04, project administration and later consumers. Include focused native test results and the exit code from `npm run verify`.
