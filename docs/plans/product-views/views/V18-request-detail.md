### Build the flow

1. **Paket** previews current project repository/branch, data classification, PBI and requirement, exact linked documents, Gherkin, NFR text/criteria/provenance and scoped entities/relationships. A source link opens its current note. A pinned attachment opens its packaged text with a separate link to the current note.
2. **Ready & Done** evaluates project definitions. In a draft, show missing approvals, uncommitted working copies and manual checks with direct repair actions. On **Paket freigeben**, re-evaluate current source versions and Ready evidence and persist one immutable revision. Freeze PBI text/revision/SHA and criteria, requirement anchor, selected attachment text/revisions/SHAs, Gherkin, destination and classification, scope, NFRs, domain, work IDs, configured definitions and Ready results. Distinguish absent historical evidence (**Stand unbekannt**) from a recorded empty set.
3. A released revision can enter **Factory-Run** through explicit **An Factory übergeben** when its baseline remains eligible. Record run ID and attempt once, then surface queue, worker pickup, clarification/reply, failure/retry and technical completion. A clarification within the frozen scope resumes work. A response that changes scope records **Änderung angefragt** and leads to a follow-up revision. A question includes the actual request scope. On completion show PR, tested commit and technical evidence in the request. V20 connects the actionable decision destination when it lands. Successful dispatch moves the PBI to **In Development**. A later business decision leaves the card’s manual completion available.
4. **Folgerevision vorbereiten** on an eligible prior revision archives its payload, gate/decision evidence and run history, retains the request ID and opens a fresh live draft with the next revision. Version-specific JSON export returns exactly the stored package. Changing attachments, the PBI revision, destination or classification can make a release stale. Changes to NFR/domain scope alone show an advisory and preserve the frozen scope and approval. Never reconstruct a historical revision from current notes.

### Data and native boundaries

**Nachweise** pairs each packaged acceptance criterion and scenario ID with evidence for this exact run and commit. Show technical review and business decision separately. In draft, **Lieferumfang bearbeiten** updates the requested scope and invalidates affected manual Ready confirmations. **Vorherige Revisionen** opens each historical package export independently.

At release, materialize the evidence the recipient may receive, resolve local wikilinks to stable artifact/revision references and calculate the package checksum over the stored release content using the approved serialization. Record the algorithm and verify the checksum against the exported payload in a regression test. Keep the native input Git SHAs, the package checksum and the later implementation test SHA distinct. See the [product handoff specification](../../../concept/Product-Engineering-Platform-Produktkonzept.md).

The project repository owns revisioned packages and append-only transition evidence. Revalidate guards on every mutation, including delayed callbacks. Detect concurrent release/retry/revision attempts, preserve old revision readback, and make duplicate run events idempotent. A delivery adapter supplies worker/CI/PR events. Bind it to a deterministic local fixture until an approved Factory contract exists in the completed groundwork. Existing [agent chat](../../../../src/application/integrations/chat/index.ts) and [local MCP](../../../../src/application/integrations/mcp/index.ts) have different responsibilities. This task can demonstrate delivery entirely in a disposable vault without creating a PR, running a remote worker or publishing.
