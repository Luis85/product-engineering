# Adding a feature

Use Items as the worked example. Its schema, rules, use cases, routed section, and dialogs extend the shared notes kit. Add a failing test for the behavior at each layer, run it, and confirm the failure before implementing that behavior. [Item contract](../contracts/item-v1.md), [Testing guide](testing.md)

## From contract to view

1. **Name the data.** Add terms to the glossary and write the record contract with field keys, schema version, filename and folder rules, editable and read-only outcomes, and the fields users can repair. Use the same English property keys in Markdown, codecs, and forms. [Glossary](../../GLOSSARY.md), [Item contract](../contracts/item-v1.md)
2. **Test and declare the domain.** Start with decoding one usable record, each field issue, and a newer schema. Then add the type with `defineNoteType` and the feature's pure rules. Items checks title uniqueness and filename size for new or changed titles. An unchanged loaded title stays eligible while the user repairs another property. [Item codec](../../src/domain/items/item-type.ts), [Item rules](../../src/domain/items/rules.ts), [Codec tests](../../tests/unit/domain/items/item-type.test.ts), [Rule tests](../../tests/unit/domain/items/rules.test.ts)
3. **Test the use cases.** Use the memory-backed fixture to cover a list, creation, edits, and removal. Declare the records with `defineRecords` for index-backed lists, optimistic field merging, rename behavior, and notices. Validate form inputs through the same domain rules and emit typed errors. Items serializes writes so two concurrent creates cannot claim the same title. [Item records](../../src/application/items/list.ts), [Item use cases](../../src/application/items/use-cases.ts), [Fixture](../../tests/support/items/fixture.ts), [List test](../../tests/unit/application/items/list.test.ts), [Write tests](../../tests/unit/application/items/create-delete.test.ts), [Edit tests](../../tests/unit/application/items/update.test.ts)
4. **Add the module texts and registration.** Provide one typed catalog per supported language. Register error tags, the describer, note types, and section or route declarations in the application manifest. Keep values stored in the vault stable across languages. Add exact tests for messages where the feature specifies copy and test that each field issue is worded. [Items manifest](../../src/application/items/module.ts), [Items message tests](../../tests/unit/application/items/i18n.test.ts), [Error handling](error-handling.md)
5. **Test the routed view.** Mount the production surface against test adapters. Cover loading, empty and failure states, then exercise create, edit, delete, conflicts, and focus. Use the record screen and TanStack Form composables for these flows. Items calls `useStream` for its list and maps its route to a lazy section component. [Items screen](../../src/presentation/items/components/ItemSettings.vue), [Items form](../../src/presentation/items/use-item-form.ts), [Record screen](../../src/presentation/notes/use-record-screen.ts), [Presentation tests](../../tests/dom/presentation/items)

Regenerate the analyzer configuration with `npm run fallow:config` after editing the application registry. The gate checks its freshness. Import public module entries across boundaries. The notes adapter entry is for infrastructure, the shell host entry is for plugin lifecycle code, and presentation screen manifests feed the application surface. Dependencies run toward notes and shell. Keep cross-feature dependencies acyclic. [Analyzer inputs](../../configs/fallow.config.mjs), [ESLint configuration](../../eslint.config.mjs), [Architecture guide](architecture.md)

Wire any new module event into the shared event union. Add any new port layer to `AppAdapters` and provide its implementation in the live host, the harness, and the test adapters as applicable. Register new Nuxt UI components in the stylesheet's `@source` lists, and register icons in `SHELL_ICONS`. The architecture guide describes which imports and entry points are allowed for each layer. ## New-view checklist

- Check enable, disable, re-enable, and unload with work pending. Confirm the view, subscriptions, and modal portals close with their scopes.
- Exercise missing, corrupt, partially invalid, and newer settings data. Edit a setting from its native tab or its routed section according to the setting's designated location.
- Switch the host theme with the view open. Move a view with an open sheet to a pop-out. Mount two views and close one while keeping the other usable.
- Confirm keyboard navigation, meaningful labels, modal focus and restoration, the first invalid field focus, and wrap and contrast at 320 px. Keep a blocked action focusable with `aria-disabled` and guard its handler.
- Run `npm run verify` and read its exit code. Run the native suite for lifecycle, settings tab, theme, pop-out, view state, or vault changes. Record any personal-vault checks separately from fixture runs. [Testing guide](testing.md)
