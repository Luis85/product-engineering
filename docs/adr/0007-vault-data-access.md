# ADR 0007 · Vault data access

## Context

Product Engineering records share Markdown files with Obsidian, Sync, and other editors. A record needs a stable identity across moves and renames. Saving an edit must preserve the user's writing and account for any changes made since the form opened.

## Decision

Recognize records by their `schema` marker and identify them by `id`. An ID combines the note type and a lowercase UUID. The type declaration defines a version, migrations, and the ordered set of frontmatter fields. Fields use flat English keys across Markdown, the codec, and form values. Migrations run in memory during decoding and persist with a successful save. The Item contract is the first example. [Item v1 contract](../contracts/item-v1.md), [Note codec](../../src/domain/notes/codec.ts), [Record ID](../../src/domain/notes/record-id.ts)

The application reads and writes notes through `NoteStore`. The Obsidian adapter reads Markdown paths and cached frontmatter through the vault and metadata cache. It normalizes paths, creates folders and files through the vault, and delegates renames and trash moves to the file manager. `NoteOpener` opens a note in Obsidian and `IdGenerator` supplies UUIDs. The same use cases take scoped in-memory adapters in tests and the browser harness. [Ports](../../src/application/notes/ports.ts), [Obsidian store](../../src/infrastructure/obsidian/notes/note-store.ts), [Obsidian opener](../../src/infrastructure/obsidian/notes/note-opener.ts), [Memory store](../../src/infrastructure/memory/notes/memory-note-store.ts)

The root folder and the type's subfolder determine the creation path. Records stay discoverable after a move anywhere in the vault. The root also scopes the scan for unreadable YAML in Data issues. `clashKey` compares names in Unicode NFC with default lowercase mapping. Folder lookup prefers the existing exact spelling, then the first matching spelling in code-unit order. A taken filename receives the first free suffix in the range ` (2)` through ` (100)`. The record kit follows a title change when the existing filename follows the old title. [Folder and rename plans](../../src/application/notes/paths.ts), [Filename rules](../../src/domain/notes/file-name.ts), [Record kit](../../src/application/notes/record-kit.ts)

The Markdown body belongs to the user. Updates call `vault.process` so the editor receives the current raw text inside the write. The callback calculates a frontmatter patch and edits just the affected key lines. A re-parse must match the expected keys, order, and values before the edit may reach disk. The editor preserves the BOM, line endings, body, untouched key bytes, and a trailing comment on a changed single-line field. When a field becomes a list, that comment stays on the key's line. An uncertain layout produces a typed refusal so the user can repair the note in Obsidian. [Application text editor](../../src/application/notes/note-text.ts), [Domain line editor](../../src/domain/notes/note-text.ts)

Obsidian 1.15.1's `processFrontMatter` rewrote the whole block on Windows. The probe observed changes to leading zeros, decimal precision, comments, and flow lists. `getFrontMatterInfo` and the metadata cache also disagreed on BOM and alternate closing fences. The line editor recognizes the cached block and accepts a smaller set of closing fences for safe writes. The live suite exercises 900 YAML values and checks file bytes after direct writes and form saves. [Live write fidelity](../../tests/e2e/specs/note-write-fidelity.e2e.ts), [Fidelity scenarios](../../tests/support/notes/scenarios.ts)

The merge compares each edited field with its loaded and current values inside the atomic callback. Untouched fields retain the current values. A changed field can replace the loaded value or agree with the current value. Two different changes to the same field return a typed conflict and leave the note unchanged. The form shows all three values and uses the current values as the comparison baseline after the user resolves the conflict. Missing values and `null` compare as unset. An invalid field stays available for repair, and a newer schema or an unusable identity makes the record read-only. [Merge rules](../../src/domain/notes/write.ts), [Record form](../../src/presentation/notes/use-record-form.ts), [Conflict choices](../../src/presentation/notes/components/ConflictChoice.vue)

The Knowledge editor uses `NoteStore.updateContent` for an explicit body save. The callback sees the current frontmatter and body together. An edited body must still match its loaded base or agree with the current body. The same callback applies any frontmatter patch, preserves the original frontmatter line endings and returns the saved Markdown. `NoteStore.readContent` supplies the exact persisted text for export. [Knowledge v1 contract](../contracts/knowledge-v1.md)

`appNoteTypes` derives the registered declarations from the application manifest. The in-memory index subscribes before host callbacks start and builds from the store at `VaultReady`, when every current Markdown file has a cache entry. It ignores earlier file events and re-reads paths from metadata, rename, and delete events that follow. Batches close after 100 ms of quiet or one second. `noteSnapshot` and `noteChanges` serve record lists. The record kit supplies the shared list, form, write, and conflict flow. A failed read produces an index error with a rebuild action. [Type registry](../../src/application/note-types.ts), [Index worker](../../src/application/notes/index-live.ts), [Event batching](../../src/application/notes/index-batches.ts), [Event system ADR](0004-event-system.md)

The local MCP tools expose `id`, `title`, `status`, and optional `due` for items the user selected to share. Both tools read records through the application. [MCP item tools](../../src/application/integrations/mcp/shared-item-tools.ts)

## Consequences

Disk remains the source of truth. Views can follow indexed snapshots, while writes still resolve the live identity and guard it inside the store operation. Note content in a conflict stays available to the edit form. The typed error text and diagnostic logs omit the values. [Record write adapter](../../src/application/notes/records.ts), [Conflict privacy tests](../../tests/unit/application/notes/issues.test.ts)

A Markdown file without an Obsidian metadata cache entry can hold `VaultReady` open indefinitely. Each type publishes its own snapshot, so a consumer joining two types can observe different points in a batch. Record references, a direct ID lookup, and a date source for local midnight remain future extensions. The note-store contract runs on the memory adapter and the Obsidian double. The desktop suite exercises selected shared vault facts, write fidelity, folder case matching, and readiness on Windows. Live macOS verification of decomposed folder spellings remains pending.
